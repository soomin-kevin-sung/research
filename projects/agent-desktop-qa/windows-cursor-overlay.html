Windows에서 agent-desktop 커서 오버레이 검증

Vercel Labs의 agent-desktop 1.3.1을 Windows x64에서 검증했다. npm 바이너리의 임시 복사본을 agent-desktop.exe로 실행하자 오버레이가 활성화됐다. 커서 크기 0.8과 이름표 QA를 적용한 계산기 시연에서 7 + 5 = 12를 확인했다.

검증 목적과 결과

QA 시연을 보는 사람이 에이전트가 어떤 컨트롤을 눌렀는지 따라갈 수 있도록 커서 오버레이 동작과 표시 옵션을 확인했다.

  • npm의 agent-desktop-win32-x64.exe에서 cursor-overlay enable은 rendered: false를 반환했다. 계산기 조작은 성공했고 오버레이 동작에는 PLATFORM_NOT_SUPPORTED가 기록됐다.
  • 같은 바이너리의 임시 복사본을 agent-desktop.exe로 실행했을 때 rendered: true를 받았다. npm 설치 파일은 그대로 두었다.
  • 초기 시연에서는 크기 1.7과 이름표 agent-desktop을 사용했다. 후속 시연에서 렌더러가 크기 0.8과 이름표 QA를 반환했다. 접근성 트리에서 버튼을 찾아 차례로 누른 뒤 결과 표시에서 12를 확인했다.

재현 절차

npm 패키지의 Windows x64 바이너리를 임시 폴더에 agent-desktop.exe라는 이름으로 복사한 뒤, 해당 폴더의 PowerShell에서 실행한다.

$session = (.\agent-desktop.exe session start --no-trace | ConvertFrom-Json).data.session_id
.\agent-desktop.exe --session $session cursor-overlay enable --size 0.8 --label QA
.\agent-desktop.exe --session $session snapshot --app CalculatorApp.exe --max-depth 20

계산기가 열려 있는 상태에서 각 스냅샷의 최신 참조로 click을 실행한다. 지우기, 7, 더하기, 5, 등호 순서로 조작하고 새 스냅샷에서 결과를 확인한다. 시연이 끝나면 같은 세션에서 cursor-overlay disable과 session end를 실행한다.

원인과 남은 검증

공개 이슈에서는 Windows 렌더러를 시작할 때 실행 파일 이름을 검사하고, npm 배포본의 아키텍처 접미사가 붙은 이름이 이 검사에 걸린다고 설명한다. 로컬에서 동일 바이너리의 이름만 바꾸었을 때 렌더링 상태가 달라졌다. 조사 시점에 수정 PR은 열려 있었다. 이슈 #422 · 이슈 #619 · 수정 PR #456

초기 시도에서는 플랫폼 오류를 보고 실행 파일 이름의 영향을 확인하기 전에 Windows 지원을 의심했다. 같은 바이너리로 이름만 바꾼 비교에서 우회 방법을 확인했다. 대상 앱에서 오버레이를 활용한 시연과 저장 충돌 재검증은 남아 있다. 기존 QA 실행 기록
