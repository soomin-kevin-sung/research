## 5. B10: 관리자 소유 폴더를 쓰기 경로로 지정

`targets\admin-owned`를 UAC 세션에서 만들었습니다. 소유자는 Administrators이고 상속을 끊었습니다. ACE는 SYSTEM·Administrators 모든 권한, 사용자 수정, `Users` 읽기·실행입니다. 사용자는 안의 파일을 고칠 수 있지만 이 폴더의 DACL을 바꿀 권한(`WRITE_DAC`)은 없습니다.

| 구성 | 지정 방법 | 결과 |
| --- | --- | --- |
| QwenPaw 관리자 | 쓰기 가능 mount | **쓰기 허용** 5/5. 승격된 QwenPaw가 샌드박스 계정 ACE를 추가하고, 샌드박스가 끝나면 지움. 측정 후 명시적 ACE는 처음 4개 그대로 |
| QwenPaw 비관리자 | 쓰기 가능 mount | **경고만 남기고 실행**, 쓰기 거부 5/5. 로그: `SetNamedSecurityInfoW(...) failed: rc=5`, `Failed to set ACE on mount` |
| Codex `unelevated` | 추가 쓰기 경로(`isob10` 프로필) | 실행, 쓰기 거부 1/1. 표준 오류 출력에 경고 없음 |
| Codex `elevated` | 추가 쓰기 경로 | **명령을 실행하지 않음** 5/5. 갱신 단계가 이 폴더를 `READ_CONTROL \| WRITE_DAC`로 열지 못해 `setup refresh had errors`로 종료. UAC 창은 뜨지 않았고 샌드박스 계정도 바뀌지 않음 |

- **세 가지 처리 방식.** 사용자 권한으로 ACE를 추가할 수 없는 경로를 쓰기 경로로 받았을 때 처리가 갈렸습니다.
  - QwenPaw 관리자: 관리자 권한으로 ACE를 추가해 쓰기를 허용합니다.
  - QwenPaw 비관리자와 Codex `unelevated`: 명령은 실행하고, 그 경로만 쓰기가 안 됩니다.
  - Codex `elevated`: 명령 자체를 거부합니다.
- **Codex 측 기록.** Codex `elevated`는 실제 `~/.codex/.sandbox/setup_error.json`에 이 오류를 기록했고, `cap_sid`에 이 경로의 항목 1개를 추가했습니다(11장).
