# Windows 네이티브 격리의 보안 한계

기존 조사에서 고정한 에이전트 버전의 공식 문서와 소스를 검토했습니다. 아래의 **지원**은 해당 정책을 표현하고 적용하는 경로가 문서나 소스에 있다는 뜻입니다. 호스트별 동작은 미실측입니다. **미지원**은 경로가 해당 요구를 표현하거나 적용하지 못하는 경우, **시작 거부**는 정책을 지킬 수 없을 때 워크로드를 실행하지 않는 경우입니다. **비격리 실행**은 워크로드가 Windows 호스트 권한으로 시작되는 경우입니다.

## 함께 확인할 경계

- **이름 열거와 파일 조작.** 상위 폴더 열거를 허용하면 보호된 폴더 이름이 보일 수 있습니다. NTFS에서는 파일 삭제·이름 변경에 해당 객체의 권한과 부모의 자식 삭제 권한이 관여하므로, 읽기나 내용 쓰기의 거부만으로 무결성을 판정할 수 없습니다. [Microsoft 파일 접근 권한](https://learn.microsoft.com/en-us/windows/win32/fileio/file-access-rights-constants) · [Microsoft 삭제 권한 규칙](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-deletefilew#remarks)
- **경로 규칙과 객체 보호.** Codex MXC 소스는 심볼릭 링크·정션으로 표현되는 동등한 경로에 더 엄격한 규칙을 적용하지만, 하드 링크 이름에는 경로별 권한이 유지되고 볼륨 루트 확장 후 별칭 사이의 하위 권한이 달라질 수 있다고 명시합니다. 경로 하나의 거부를 파일 객체 전체의 보호와 같은 보장으로 해석할 수 없습니다. [Codex 고정 버전 MXC 설명](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/mxc-sandbox/README.md)
- **적용 시점과 설정 실패.** Codex MXC·`elevated`의 거부 글롭은 프로세스 시작 때 확장되므로, 나중에 생긴 일치 항목에는 같은 프로세스의 기존 글롭이 동적으로 적용되지 않습니다. QwenPaw AppContainer는 프로필 초기 생성 시 ACL을 설치하고 재사용 시 같은 절차를 다시 수행하지 않습니다. 관리자 Restricted Token은 방화벽 설치 결과를 초기 설정 호출부에서 검사하지 않으므로 설치 실패 시 전체 차단을 가정할 수 없습니다. [Codex 글롭 시점](https://learn.chatgpt.com/docs/windows/windows-sandbox#mxc-compatibility) · [QwenPaw AppContainer 초기화](https://github.com/agentscope-ai/QwenPaw/blob/v2.3.0.post1/src/qwenpaw/sandbox/windows_appcontainer_sandbox.py) · [QwenPaw 관리자 초기화](https://github.com/agentscope-ai/QwenPaw/blob/v2.3.0.post1/src/qwenpaw/sandbox/windows_elevated_sandbox.py)
- **네트워크와 환경 변수.** Codex MXC의 관리형 네트워크에는 호스트 루프백도 포함됩니다. OpenClaw Gateway MXC의 번들 SDK는 현재 문서화된 버전에서 호스트 프로세스 관찰 권한이 있는 주체에게 명령·환경 값이 노출될 수 있습니다. QwenPaw AppContainer에서 도메인 목록을 주면 세부 제한 대신 네트워크 capability를 부여하며, QwenPaw Windows 샌드박스의 환경 변수 허용 목록은 구현되지 않았습니다. [Codex 네트워크 경계](https://learn.chatgpt.com/docs/windows/windows-sandbox#mxc-compatibility) · [OpenClaw MXC 요청 전달](https://github.com/openclaw/openclaw/blob/v2026.11.6/extensions/mxc/README.md) · [QwenPaw 제약](https://github.com/agentscope-ai/QwenPaw/blob/v2.3.0.post1/website/public/docs/security.en.md#current-limitations)
- **종료와 상태 관리.** OpenClaw의 IsolationSession 패키징 기록은 SDK의 단일 실행 취소가 모든 하위 프로세스 종료를 보장하지 않는다고 명시합니다. 개발 브랜치에서 별도 개선을 검증하고 있으나 설치된 Store 패키지의 보장은 추가 확인이 필요합니다. Gateway 서비스 중지와 격리 세션 제거도 별도 상태입니다. [Gateway 패키징 검증 기록](https://github.com/openclaw/openclaw-windows-packaging/blob/main/docs/mxc-compatibility-evidence.md)

실측에서는 동일한 합성 작업 영역에서 일반 폴더의 읽기·쓰기가 계속 가능해야 합니다. 보호 경로는 **읽기 전용**과 **접근 거부**로 나누고, 열거·내용 읽기·쓰기·삭제·이름 변경을 별개 결과로 남깁니다. 정책을 받아들이지 않고 시작이 차단된 경우에는 시작 거부로 기록하고, 실행된 프로세스의 접근 차단 결과와 구분합니다. [실측 프로토콜](../protocol.md)

## 파일 외 자원과 작업 호환성

파일 작업이 성공해도 빌드, 테스트, 로컬 서비스, GUI 자동화에 필요한 권한은 따로 확인해야 합니다. 작업의 필수 자원이 막히는 경우는 **호환성 제한**, 금지하려던 자원이 열려 있는 경우는 **정책 미충족**으로 기록합니다.

| --- | --- | --- |
| 로컬 서비스·포트·외부 네트워크 | 패키지 복원, 사내 API, 로컬 DB, 브라우저에서 개발 서버 열기 | Codex MXC의 관리형 네트워크는 IPv4·IPv6 호스트 루프백을 양방향으로 허용하고 프록시 정책은 프록시를 거친 연결에 적용합니다. 따라서 호스트 로컬 서비스 접근까지 막아야 하는 구성은 별도 판정이 필요합니다. ### 솔루션별로 남는 확인 항목

- **MXC ProcessContainer.** Codex, OpenClaw Gateway, Hub를 별도 조건으로 둡니다. 실제 쓰는 포트·파이프·GUI와 동일한 종류의 합성 자원에 대해, 허용돼야 하는 작업과 차단돼야 하는 작업을 확인합니다. Microsoft SDK 일반 기능과 제품에 노출된 기능을 각각 기록합니다. [MXC 네트워크 정책](https://github.com/microsoft/mxc/blob/main/docs/backends/process-container/networking.md) · [MXC UI 정책](https://github.com/microsoft/mxc/blob/main/docs/backends/process-container/UIPolicy_Schema.md)
- **MXC IsolationSession과 관리자 전용 계정.** 사용자별 구성·인증과 전경·백그라운드 작업 상태를 따로 확인합니다. 사용자 프로필의 격리 여부를 사내 서비스 연결 정책으로 확대 해석할 수 없습니다. [OpenClaw 패키징 검증](https://github.com/openclaw/openclaw-windows-packaging/blob/main/docs/mxc-compatibility-evidence.md) · [Windows 제한 토큰](https://learn.microsoft.com/en-us/windows/win32/api/securitybaseapi/nf-securitybaseapi-createrestrictedtoken)
- **AppContainer와 비관리자 제한 토큰.** AppContainer의 capability·레지스트리·장치 권한과 제한 토큰의 ACL·실행 계정을 각각 기록합니다. QwenPaw Windows 후보는 환경 변수 허용 목록과 프로세스 수·메모리 한도의 미집행을 함께 기록합니다. [Microsoft AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation) · [QwenPaw 제약](https://github.com/agentscope-ai/QwenPaw/blob/v2.3.0.post1/website/public/docs/security.en.md#current-limitations)
- **TinyBox 미선택과 호스트 셸.** OpenHuman의 유효 백엔드가 `NoopBackend`이거나 에이전트가 Windows 호스트 셸을 사용하면 해당 계정과 정책의 유효 권한을 관찰합니다. 별도 환경 변수 정리, 도구 승인, 시간 제한은 각각 결과에 반영합니다. [OpenHuman 실행 구현](https://github.com/tinyhumansai/openhuman/blob/v0.64.15/crates/openhuman-core/src/sandbox/ops.rs) · [도구 승인과 호스트 셸](solutions/tool-approval.md)
