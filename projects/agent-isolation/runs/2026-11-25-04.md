- **준비.** [상위·하위 폴더 측정 준비](probe-token-backends-nest-prep.py)로 시험 폴더를 최소 구성으로 다시 만들었습니다. 승격되지 않은 세션에서 만들었으므로, 대상 폴더의 소유자와 DACL은 네 구성에서 같습니다.

## B: 상위 쓰기 차단 + 하위 쓰기 허용

| 확인 | QwenPaw 비관리자 | Codex `unelevated` | Codex `elevated` | QwenPaw 관리자 |
| --- | --- | --- | --- | --- |
| 실행 | 실행 5/5 | 실행 5/5 | 실행 5/5 | 실행 5/5 |
| 상위 폴더 파일 읽기 | 허용 5/5 | 허용 5/5 | 허용 5/5 | 허용 5/5 |
| 상위 폴더에 새 파일 쓰기 | 거부 5/5 | 거부 5/5 | 거부 5/5 | 거부 5/5 |
| 하위 폴더에 새 파일 쓰기, 기존 파일 덮어쓰기 | 허용 5/5 | 허용 5/5 | 허용 5/5 | 허용 5/5 |
| **쓰기 허용한 하위 폴더 자체 삭제**(`w-empty`) | **허용** 5/5 | **허용** 5/5 | **허용** 5/5 | **허용** 5/5 |
| 실행 뒤 하위 폴더 `w`의 명시적 ACE | 없음(정리 함수가 지움) | capability SID 허용 1개 | 샌드박스 그룹 허용 1개, capability SID 허용 2개 | 없음(정리 함수가 지움) |

- **설정대로 동작했습니다.** 상위 폴더 쓰기는 거부되고 하위 폴더 쓰기는 허용됐습니다.
  - Codex 두 구성은 실행 뒤에도 하위 폴더에만 허용 ACE(`0x1301bf`, 하위 상속)가 남아 있었고, 상위 폴더에는 아무것도 없었습니다.
  - QwenPaw 두 구성은 실행 중에만 ACE를 두고 작업자 종료 때 정리 함수가 지워서, 실행 뒤 기록에는 ACE가 없었습니다.
- **하위 폴더 자체를 지울 수 있었습니다.** 허용 ACE의 권한에 `DELETE`가 들어 있기 때문입니다. 상위 폴더가 읽기 전용이어도 쓰기 허용한 하위 폴더는 샌드박스 명령이 지울 수 있습니다. 이 측정에서는 빈 폴더만 지웠습니다.

## A: 상위 읽기 거부 + 하위 허용

| 확인 | QwenPaw 비관리자 | Codex `unelevated` | Codex `elevated` | QwenPaw 관리자 |
| --- | --- | --- | --- | --- |
| 실행 | 실행 5/5, 경고 로그만 남김 | **실행 거부** 5/5 | 실행 5/5 | 실행 5/5 |
| 상위 폴더 파일 읽기 | 허용 5/5 | — | 거부 5/5 | 거부 5/5 |
| 상위 폴더 목록 보기 | 허용 5/5 | — | 거부 5/5 | 거부 5/5 |
| 읽기만 허용한 하위 폴더(`open`)의 파일 읽기 | 허용 5/5 | — | **거부** 5/5 | **허용** 5/5 |
| 쓰기 허용한 하위 폴더(`open-w`)의 파일 읽기 | 허용 5/5 | — | 허용 5/5 | 허용 5/5 |
| 쓰기 허용한 하위 폴더에 쓰기 | 허용 5/5 | — | 허용 5/5 | 허용 5/5 |
| 호스트가 지운 명시적 거부 ACE | 0 | 0 | 회차마다 2개 | 0(정리 함수가 지움) |

- **QwenPaw 비관리자.** 읽기 거부를 적용하지 않습니다. 로그에 `WindowsUnelevatedSandbox does not enforce deny_paths=...; the constraint is IGNORED` 경고만 남기고, 상위 폴더도 그대로 읽게 둡니다. 하위 폴더의 쓰기 허용은 적용됐습니다.
- **Codex `unelevated`.** `Restricted read-only access requires the elevated Windows sandbox backend`로 실행을 거부했습니다(종료 코드 1). 이전 측정과 같습니다.
- **Codex `elevated`.** 상위 폴더에 샌드박스 그룹 대상 거부 ACE 두 개를 달았습니다.
  - 상위 폴더 자체: `0x120089`(읽기)
  - 하위로 상속되는 것: `OI|CI|IO`, `GENERIC_READ` 포함
  - 결과는 하위 폴더 설정에 따라 갈렸습니다.
    - **쓰기 허용한 하위 폴더:** Codex가 명시적 허용 ACE(샌드박스 그룹, capability SID)를 달았습니다. Windows는 명시적 ACE를 상속된 ACE보다 먼저 확인하므로, 상속된 거부보다 이 허용이 앞서 읽기·쓰기가 됐습니다.
    - **읽기만 허용한 하위 폴더:** 아무 ACE도 달지 않아 상위에서 상속된 거부가 적용됐고, 읽지 못했습니다.
  - 읽기 경로에 ACE를 달지 않은 이유는 소스로 설명됩니다. Codex는 `Users`·`Authenticated Users`·`Everyone` 중 하나가 이미 읽기를 허용하는 경로에는 읽기 ACE를 추가하지 않습니다([소스 비교](../research/restricted-token-backends.md) 4장). 이 폴더는 시험 폴더 루트에서 `Authenticated Users` 수정 권한을 상속했습니다. 실측 결과는 이 조건과 일치합니다.
- **QwenPaw 관리자.** 상위 폴더의 읽기와 목록은 거부됐고, **하위 폴더 두 개는 읽기만 허용한 것도 포함해 모두 접근할 수 있었습니다.**
  - 실행 뒤 기록에는 ACE가 없습니다(정리 함수가 지움).
  - 소스를 보면 QwenPaw 관리자는 mount마다 capability SID와 샌드박스 계정 SID 대상 명시적 허용 ACE를 답니다. 쓰기 가능 mount에는 모든 권한, 읽기 전용 mount에는 읽기를 줍니다([`_grant_workspace_and_mounts`](https://github.com/agentscope-ai/QwenPaw/blob/v2.3.0.post1/src/qwenpaw/sandbox/windows_elevated_sandbox.py#L1612-L1640)).
  - 명시적 허용 ACE는 상위에서 상속된 거부보다 먼저 적용되므로, 읽기만 허용한 하위 폴더도 읽혔습니다. Codex `elevated`와 갈린 이유가 이것입니다.

- **Codex `elevated`.** `.key`에 샌드박스 그룹 대상 거부 ACE 네 개를 달았습니다.
  - 쓰기·삭제 거부: `0x130156`. 하위 상속용은 `GENERIC_WRITE`를 포함합니다.
  - 읽기 거부: `0x120089`. 하위 상속용은 `GENERIC_READ`를 포함합니다.
  - 작업 폴더 밖(A, [2026-11-25-01](2026-11-25-01.md) C5)에서는 읽기 거부 두 개만 달았습니다. 작업 폴더 안에서는 쓰기·삭제 거부도 함께 달았습니다.
- **QwenPaw 관리자.** 읽기·목록·쓰기·삭제를 모두 막았습니다. [2026-11-25-02](2026-11-25-02.md)의 C5에서 본 샌드박스 계정 대상 거부 ACE(`0x1f01ff`)와 같은 방식으로 보입니다. 실행 뒤에는 정리 함수가 지워 기록에 없습니다.
- **QwenPaw 비관리자와 Codex `unelevated`.** A와 같습니다. 각각 무시와 실행 거부입니다.

## 정리

| 조합 | QwenPaw 비관리자 | Codex `unelevated` | Codex `elevated` | QwenPaw 관리자 |
| --- | --- | --- | --- | --- |
| 상위 쓰기 차단 + 하위 쓰기 허용 | 됨 | 됨 | 됨 | 됨 |
| 상위 읽기 거부 + 하위 쓰기 허용 | 상위 거부가 적용되지 않음 | 실행 거부 | 됨 | 됨 |
| 상위 읽기 거부 + 하위 읽기 허용 | 상위 거부가 적용되지 않음 | 실행 거부 | **안 됨**(하위도 거부) | 됨 |
| 쓰기 가능한 작업 폴더 안 폴더 거부 | 적용되지 않음 | 실행 거부 | 됨(읽기·쓰기·삭제 모두 거부) | 됨(읽기·쓰기·삭제 모두 거부) |

- 쓰기를 허용한 하위 폴더는 네 구성 모두 폴더 자체까지 지울 수 있었습니다.
- 거부는 별도 계정 구성(Codex `elevated`, QwenPaw 관리자)만 적용했습니다. 현재 사용자 토큰을 쓰는 두 구성은 읽기 거부를 만들 수 없습니다. 읽기는 사용자 SID로 하는 첫 번째 검사만 받기 때문입니다.
- 작업 폴더 안 읽기 전용 폴더와 `.git` 등의 쓰기 차단, 작업 폴더 밖 읽기 거부 폴더의 기존·새 파일·옮겨 온 파일은 [2026-11-25-01](2026-11-25-01.md)·[2026-11-25-02](2026-11-25-02.md)의 B6과 C5·C6에서 측정했습니다.
