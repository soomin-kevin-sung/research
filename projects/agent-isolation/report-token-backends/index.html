결론

네 구성이 모두 막은 것
  • 작업 폴더 밖, 사용자만 쓰기를 허용한 파일 수정(사례 1)
  • 사용자 레지스트리 쓰기(사례 4)
  • 다른 프로그램 메모리 쓰기·스레드 만들기(사례 11)
네 구성이 모두 막지 못한 것
  • Everyone 쓰기 허용 위치(사례 2)
  • Users·Everyone이 읽을 수 있는 파일(사례 7)
  • 컴퓨터 범위 DPAPI 값(사례 8)
  • 환경 변수의 비밀값(사례 15)
  • 쓰기 허용 하위 폴더 통째 삭제(사례 18)
토큰 계정에 따라 갈린 것
  • 현재 사용자 토큰 두 구성은 사용자가 읽는 파일과 사용자 프로세스를 그대로 엶(사례 5, 6, 10)
  • Codex elevated는 별도 계정이지만 사용자 로그온 SID를 공유해 데스크톱 프로세스가 열림(사례 10). 고정 계정이라 작업 폴더끼리 공유(사례 12, 13)
  • QwenPaw 관리자만 사용자 프로세스와 옆 샌드박스를 막음(사례 10, 12). 대신 앱 전체가 관리자로 실행되고, 사용자 권한 밖 경로도 열어 줌(사례 19)
판단
  • 신뢰하는 에이전트의 실수로 작업 폴더 밖을 고치는 것은 네 구성 모두 막습니다.
  • 비밀 파일과 다른 프로그램까지 보호하려면 별도 계정과 별도 로그온 세션이 필요했습니다(QwenPaw 관리자).
  • 신뢰하지 않는 코드를 가두는 경계로는 네 구성 모두 부족합니다. 가상 머신 같은 별도 경계가 필요합니다.
측정 방법
  • 네 구성에 같은 시험 프로그램, 사례마다 5회. 막혔다고 보기 전에 같은 대상이 원래 열리는지 먼저 확인했습니다.
  • 다른 프로세스·토큰·키는 지정한 권한으로 열고 바로 닫기만 했습니다. 메모리 읽기·쓰기, 가장, 종료, 알려진 우회 기법은 시도하지 않았습니다.
  • 실제 사용 PC에서 측정 전후 상태를 기록하고 원래대로 되돌렸습니다. QwenPaw 관리자는 사용자가 승인한 관리자 세션에서 측정했습니다.
  • 네트워크 차단과 클립보드는 측정하지 않았습니다. 사례 13의 QwenPaw 관리자 프로필 분리는 직접 측정하지 않은 간접 근거입니다.
