# 실측 프로토콜

## 비교 조건

- 대상은 Windows 호스트에서 실행되는 명령과 파일 작업입니다. Windows의 프로세스·계정·세션에 정책을 적용하는 후보를 비교하며, 호스트 권한으로 실행되는 경로는 기준 동작으로 기록합니다.
- 비교 전에 Windows 에디션·빌드, 하드웨어, 실행 계정, 작업 디렉터리, 도구 버전, 타임아웃과 후보별 버전을 고정합니다. 장치별 호환성 차이가 있으면 실제 백엔드와 기능 프로브 결과를 기록하고 같은 호스트의 기준 실행과 비교합니다.
- 격리 기능을 적용하지 않은 기준 환경의 성능도 같은 호스트에서 측정합니다. 기준 환경과 후보 환경에서 합성 파일과 고정 입력으로 구성된 동일한 작업을 사용합니다.
- 후보별 기본 설정과 비교용 제한 설정을 구분해 기록합니다. 비교용 제한 설정은 작업 디렉터리 안의 읽기·쓰기를 허용하고 호스트의 시험용 데이터와 비허용 네트워크 목적지를 차단하는 것을 목표로 합니다. 지원되지 않는 기능은 `미지원`으로 표시합니다.
- 시험 데이터, 공유 경로, 네트워크 목적지는 직접 통제합니다. 비밀 대신 가짜 값을 사용합니다. 차단 항목을 실행하기 전 동일한 시험 리소스에 허용 상태에서 접근할 수 있는지 확인해, 리소스 자체의 오류를 차단으로 집계하는 일을 줄입니다.

| ISO-04 | 상속을 허용하지 않은 호스트의 가짜 환경 변수 읽기 | 값이 노출되지 않음 |

## 상위 허용과 하위 보호

| ID | 시험 조건 | 기대 결과 |
| --- | --- | --- |
| ISO-07 | 작업 영역의 상위 폴더 쓰기 허용, 그 아래 합성 폴더 읽기 전용 | 일반 작업은 성공하고, 보호 폴더의 내용 읽기는 성공하며, 쓰기·삭제·이름 변경은 차단 |
| ISO-08 | 작업 영역의 상위 폴더 접근 허용, 그 아래 합성 폴더 접근 거부 | 일반 작업은 성공하고, 보호 폴더의 내용 읽기·쓰기·삭제·이름 변경은 차단. 이름 열거 결과는 별도 기록 |
| ISO-09 | 보호 정책의 적용 시점 확인 | 기존 시험 항목과 시작 후 생긴 시험 항목을 각각 기록하고, 재시작 없이 지속 보호한다는 요구가 있으면 두 항목 모두 차단 |

하위 정책을 설정할 수 없으면 `미지원`으로 기록합니다. 실행 전에 조합을 거부한 경우는 워크로드 시작 결과에 `시작 거부`로 기록하고, 실행한 프로세스의 접근 차단과 따로 집계합니다. 비격리 실행으로 전환된 경우 실제 백엔드와 실행 계정을 남깁니다. [판정 근거](research/security-boundaries.md)

### 상위 거부와 특정 하위 허용

합성 폴더 `A`와 하위 폴더 `B`, `C`를 준비합니다. `A`는 거부하고 `B`만 명시적으로 허용하는 정책을 적용합니다. `A` 목록 조회, 이미 아는 경로로 `B` 파일 직접 읽기·쓰기, 허용하지 않은 형제 `C` 접근 결과를 각각 기록합니다. 하위 읽기 전용 허용과 읽기·쓰기 허용은 별도 조건입니다. ACL 방식에서는 부모에 허용 ACE가 없는 경우와 부모의 명시적 거부 ACE가 하위에 상속되는 경우를 각각 확인합니다.

요청한 조합을 표현할 수 없는 경우와 백엔드가 실행 전에 거부한 경우를 구분합니다. MXC는 SDK 동작과 제품이 전달한 유효 정책을 각각 확인합니다. Codex `elevated`의 읽기 전용 구간 아래 쓰기 재허용 제약은 별도 조건으로 기록합니다. [제품별 비교](research/filesystem-isolation-comparison.md#상위-거부와-특정-하위-허용)

### MXC 보호 폴더 이름 변경

쓰기 허용된 상위 폴더에 읽기 금지 합성 폴더 `A`와 시험 파일을 둡니다. 경로 거부 지원을 확인한 MXC 세션에서 먼저 `A`의 파일 읽기가 차단되는지 기록합니다.

| 경우 | 기록할 결과 |
| --- | --- |
| 샌드박스 셸에서 이름 변경 | 셸이 `A`를 `A′`로 바꿀 수 있는지 확인합니다. 성공했다면 같은 셸에서 `A′`의 시험 파일을 읽을 수 있는지 기록합니다. |
| 호스트 사용자가 이름 변경 | 새 합성 폴더로 기준 상태를 복원합니다. 샌드박스 셸을 계속 실행한 상태에서 호스트 사용자가 `A`를 `A′`로 바꿉니다. 기존 셸에서 새 경로의 시험 파일 읽기 결과를 기록합니다. |

Windows 빌드, MXC 백엔드와 경로 거부 지원 검사 결과, 상위·하위 경로의 유효 정책, 이름 변경과 읽기 각각의 성공 여부 및 오류를 남깁니다. [MXC 조사](research/solutions/mxc.md#보호-폴더-이름-변경-후-읽기-거부)

### 대체 경로와 신규 객체의 읽기 결과

- 합성 파일의 원래 경로와 이미 준비된 대체 이름에서 읽기 결과를 비교합니다. NTFS 하드 링크와 심볼릭 링크·정션은 각각 기록합니다.
- 이미 거부된 폴더 안에 생긴 새 파일, 초기 설정 시 없었던 명시적 거부 폴더, 실행 중 새로 생긴 글롭 일치 파일을 구분합니다. 같은 셸과 새 셸의 읽기 결과, ACL 방식에서는 실제 상속과 유효 거부를 기록합니다.
- QwenPaw AppContainer와 관리자 Restricted Token은 거부 ACE 설정 결과와 실제 ACL, 프로세스 시작 여부, 파일 읽기 결과를 각각 확인합니다.

### Codex 권한 확대와 읽기 거부 보존

MXC BaseContainer와 `elevated`에서 동일한 합성 경로로 비교합니다. 원래 쓰기 허용 경로, 확대 승인으로 쓸 수 있을 것으로 예상하는 경로, 그보다 넓은 범위를 관찰할 경로, 명시적 읽기 금지 경로를 구분합니다.

| 조건 | 기록할 결과 |
| --- | --- |
| 일반 실행, 확대 승인 거부, 확대 승인 허용 | 명령 시작 여부와 실제 백엔드, 합성 경로별 쓰기 성공 여부, 명시적 읽기 금지 유지 여부를 각각 기록합니다. |
| 실행에 필요한 경로 거부 기능을 선택한 백엔드가 집행할 수 없음 | 프로세스 시작 여부와 오류를 기록합니다. 선택 단계의 레거시 대체와 선택 후 시작 실패를 구분합니다. 기능 미지원 환경을 확보하지 못하면 미실측으로 남깁니다. |
| 읽기 금지 글롭을 적용한 장시간 실행 | 시작 전과 시작 후에 생긴 합성 일치 파일의 읽기 결과를 같은 프로세스에서 확인하고, 새 프로세스에서 결과를 다시 기록합니다. |

### QwenPaw Restricted Token과 차단 후 재승인

QwenPaw `2.3.0.post1`에서 `allow_read_all=True`와 합성 파일을 사용합니다. 관리자·비관리자 경로를 별도로 시험하고, 실제 백엔드와 셸 실행 계정, 거버넌스 판정, 적용된 ACL을 기록합니다. 비관리자 기본 경로를 측정할 때는 Web Console의 선택 기능인 **Deny Paths Protection**을 끕니다. 재승인 통합 시험은 `security.sandbox_enabled`를 켜고 첫 호출이 실제 샌드박스에서 실행됐는지 확인합니다.

| 항목 | 확인할 결과 |
| --- | --- |
| 작업 폴더 안팎의 쓰기 | 작업 폴더 안의 허용 경로는 쓸 수 있는지 확인합니다. 모든 쓰기 허용 경로 밖에 합성 경로를 두고, 같은 실행 계정의 일반 토큰으로는 쓸 수 있지만 제한 토큰으로는 차단되는지 기록합니다. |
| 명시적 읽기 거부 | 백엔드 직접 시험에서 설정 전에 합성 경로를 만들고 `SandboxConfig.deny_paths`에 전달합니다. 통합 거버넌스는 기본 거부 경로 목록을 사용하므로 백엔드 직접 시험과 결과를 구분합니다. 거부 적용 전에 같은 계정으로 합성 파일을 읽을 수 있는지 확인합니다. 관리자 경로의 접근 거부 ACE와 실제 읽기 결과를 기록하고 비관리자 기본 경로와 비교합니다. |
| 차단 감지와 재승인 | 허용 범위 밖 합성 경로의 쓰기를 사용해 실제 OS 차단, QwenPaw의 위반 분류, 재승인 질문 표시를 각각 기록합니다. 승인·거부·응답 만료 후 재시도 여부와 실행 계정·격리 여부를 확인합니다. 모델이 격리 실행만 허용한 분기도 별도 검증합니다. |

차단 감지 시험에서는 종료 코드, 표준 출력·표준 오류, 도구 결과 상태와 승인 서비스 결과를 각각 남깁니다. 정상 실행과 격리와 관계없는 명령 실패에서도 재승인 요청 여부를 확인합니다. 일반 분기에서 위반으로 분류돼 사용자에게 질문한 경우, 승인은 QwenPaw 호스트 프로세스의 Windows 계정으로 재시도, 거부·응답 만료는 재시도 없음이 기대 결과입니다. 거부와 만료는 승인 서비스 기록에서 구분합니다. 모델이 격리 실행만 허용했고 결과가 `DENIED`인 경우에는 재승인 질문과 호스트 재시도가 모두 없어야 합니다. 승인으로 저장된 규칙이 다음 시험에 영향을 주지 않도록 각 조건은 초기 허용 목록이 같은 독립 상태에서 확인합니다.

## 성능 및 운영 관찰

고정 워크로드는 작은 로컬 저장소를 읽고, 지정 파일을 수정하고, 외부 다운로드 없이 테스트를 실행하는 작업입니다. 입력 파일과 예상 출력은 후보 비교 전에 고정합니다.

| 지표 | 측정 방법 |
| --- | --- |
| 시작 시간 (ms) | 환경 생성 요청부터 첫 명령 실행이 확인될 때까지 |
| 작업 시간 (ms) | 고정 작업 명령 실행부터 종료까지 |
| 최대 메모리 (MiB) | 같은 관측 범위에서 실행 중 최고치. 관측 범위가 다르면 별도 표기 |
| 성공률 | 기대한 파일 변경과 테스트 결과를 모두 충족한 횟수 / 전체 시도 |
| 설정·운영 | 최초 설치와 제한 정책 적용에 걸린 시간, 필요한 권한, 오류 로그 위치, 종료·정리 절차 |

- 초기화 비용과 캐시가 준비된 상태의 비용을 따로 기록합니다. 환경 생성 방식과 캐시 초기화 여부를 함께 남깁니다.
- 성능 측정은 후보·조건별 5회로 시작하고, 개별 값과 중앙값, 최솟값, 최댓값을 남깁니다. 실패한 실행도 전체 시도에 포함하고, 성공 실행의 시간 통계와 구분합니다.
- 결과에는 기준 환경과의 차이를 단위와 함께 제시합니다. 기대한 격리 동작을 충족했는지 먼저 확인하고, 충족한 후보는 성능과 운영 부담을 함께 비교합니다.
