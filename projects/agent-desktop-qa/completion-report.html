agent-desktop QA 연구 완료 보고서

Windows에서 agent-desktop이 실제 대상 WebView2 앱의 사용자 흐름을 검증할 수 있는지 조사했다. 온보딩을 릴리스 후보의 수동 QA 체크에 넣을 수 있는 범위로 확인했다. 기존 Playwright와 네이티브 E2E는 PR 회귀 검사에 사용한다.

검증 결과

  • 브라우저 에디터 저장 테스트 5개와 Windows 네이티브 파일 E2E가 통과했다. 네이티브 E2E에서 외부 변경 충돌 시 초안과 디스크 파일이 보존됐다. 저장 충돌 실행 기록
  • WebView2 렌더러 접근성을 강제로 켠 조건에서 agent-desktop이 온보딩의 다음과 건너뛰기를 눌렀다. 접근성 스냅샷과 DOM에서 2 / 3 표시와 안내 종료를 확인했다. WebView2 실행 기록
  • Windows npm 바이너리의 임시 복사본을 agent-desktop.exe로 실행하자 오버레이가 활성화됐다. 계산기에서 7 + 5 = 12를 확인했고, WebView2 온보딩도 크기 0.8과 이름표 QA로 재실행했다. 오버레이 검증 보고서

도입 범위와 남은 검증

온보딩은 새 임시 프로필에서 실행하고 각 클릭 뒤 기대한 UI 상태로 판정한다. 증거 수집과 독립 3회 실행을 통한 스크립트 전환 기준을 정리했다. QA 운영 가이드

기본 WebView2 실행에서는 온보딩 버튼의 참조가 노출되지 않았다. 접근성을 강제로 켠 경우에도 설정 버튼은 성공 응답 뒤 화면 전환이 없었다. 도구가 대상 창을 전경으로 가져오지 못해 저장 충돌 PoC는 Ctrl+S에 도달하지 못했다. 프로젝트는 종료하되 저장 충돌 PoC의 반복 실행 기준은 미충족으로 남겼다. 저장 충돌 프로토콜

회고

같은 바이너리의 실행 파일 이름만 바꾼 비교로 오버레이 문제를 좁혔다. 초기에는 플랫폼 오류를 Windows의 기능 제약으로 해석했고, 온보딩이 완전히 표시되기 전에 설정 버튼을 검사하기도 했다. 이후 공식 이슈를 확인하고, 기대 UI가 나타날 때까지 기다린 뒤 클릭 후 화면을 다시 읽었다. 이 확인 방식이 후속 QA의 판정 기준이다.
