# 실행 2026-11-23-02

Windows의 실제 대상 Tauri 앱에서 agent-desktop이 WebView2 내부 UI를 읽고 조작할 수 있는지 확인했다. 앱 빌드는 [첫 실행](2026-11-23-01.md)과 동일하며 agent-desktop은 `1.3.1`, WebView2는 `157.0.4341.60`이다. 조건마다 임시 앱 데이터와 WebView2 프로필을 사용했다. Playwright CDP는 준비 상태 및 조작 결과의 독립 확인에 사용했다.

| 조건 | 결과 |
| --- | --- |
| 접근성 강제 옵션 없이 실행 | 앱 창의 스냅샷은 반환됐지만 온보딩의 `건너뛰기` 참조를 찾지 못했다. |
| `--force-renderer-accessibility`로 실행, 온보딩 | agent-desktop이 `다음` 버튼을 클릭했다. UI Automation의 새 스냅샷과 DOM 양쪽에서 `2 / 3`을 확인했다. 이어 `건너뛰기`를 눌러 온보딩 컨트롤이 접근성 트리에서 사라지고 DOM에서도 숨겨졌음을 확인했다. |
| 강제 옵션, 설정 열기 | `설정`은 `menubutton`으로 노출됐다. CLI 성공 응답에도 설정 페이지는 열리지 않았다. 전경을 확보한 후 마우스로 누르는 별도 시도는 창 활성화 단계에서 중단됐다. |

강제 옵션은 테스트 프로세스의 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`에만 넣었다. UI 조작 결과는 동작 후 스냅샷이나 DOM으로 확인했다. 온보딩의 통과 결과를 설정 조작이나 편집기 입력까지 확대할 수 없다.

원본은 프로젝트의 `local/`에 있다. 기본 조건은 `webview-default-iyeBGU/`, 온보딩 통과 조건은 `webview-forced-9iS8NU/`, 설정 클릭 시도는 `webview-forced-FOwdxS/`, 전경 확보 실패는 `webview-forced-UEeuDO/`다.

오버레이를 추가한 재실행에서는 임시 `agent-desktop.exe`로 커서 크기 `0.8`과 이름표 `QA`를 지정했고 렌더러가 `rendered: true`를 반환했다. `다음`과 `건너뛰기`를 누른 뒤 진행 표시와 안내 종료를 다시 확인했다. 원본은 `local/webview-forced-2GIgk5/`에 있다.
