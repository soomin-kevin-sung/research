## 3. Git Bash 실행 순서 (각 5회)

같은 설치의 Git Bash는 모두 전역 이름 공간의 디렉터리 `\BaseNamedObjects\msys-2.0S5-<설치 해시>` 하나를 같이 씁니다.

- 이 PC에서는 사용자의 Git Bash 터미널이 늘 떠 있어서, 설치본으로는 「사용자 Git Bash가 먼저 떠 있는」 경우만 잴 수 있습니다.
- 나머지 순서는 Git의 MSYS2 파일(`usr\bin`, `etc`)을 시험 폴더에 복사해 쟀습니다. 복사본은 자기 설치 경로에 따른 별도 디렉터리를 쓰고, 다른 프로세스는 그 디렉터리를 쓰지 않습니다.
- 매 회차 시작 전에 복사본 디렉터리가 없는 것을 확인했습니다(5/5).
- 명령은 2026-11-26-02 T5와 같습니다(echo, 파이프라인, 명령 치환, 백그라운드 `sleep` 뒤 `wait`).

| 순서 | 샌드박스 | 사용자 쪽 | MSYS2 디렉터리(소유자, DACL) |
| --- | --- | --- | --- |
| 가. 사용자 Git Bash가 떠 있음(설치본) → 샌드박스 | 5/5. `bin\bash.exe` 실행기도 5/5 | — | 사용자, Everyone에 `CCDCLCSWRC` |

- **디렉터리.** 먼저 시작한 쪽이 디렉터리를 만들고 그 계정이 소유자가 됩니다. DACL은 누가 만들든 Everyone에 같은 권한입니다. Codex 목록에는 Everyone이 있어 어느 순서에서도 열립니다.
- **디렉터리 안 객체.**
  - 공용 section `shared.5`와 `tty_list::mutex.0`은 먼저 만든 계정이 소유하고 DACL이 NULL입니다(누구나 모든 권한). 그래서 사용자와 샌드박스가 서로 쓸 수 있습니다.
  - 사용자별 section `<SID>.1`과 프로세스별 `cygpid.*`는 만든 계정에만 권한을 줍니다. 호스트는 샌드박스가 만든 이 객체의 보안 정보도 읽지 못했습니다(`0xC0000022`).
- 2026-11-26-02의 비관리자 두 구성에서 막힌 `CreateFileMapping <SID>.1`은 사용자별 section이고, Codex `elevated` 구조에서는 계정마다 따로 만들어집니다.
- 복사본의 `bin\bash.exe`(Git 실행기)는 Git 폴더 전체가 필요해서(`Top-level not found`) 복사본 경우에서는 빼고, 설치본에서만 쟀습니다.

## 5. PowerShell 시작 위치와 상위 폴더 목록 권한 (각 5회)

작업 폴더는 `시험 루트\rt\pwsh\p1\p2\ws`입니다(capability SID·그룹 수정 ACE). `pwsh`·`p1`·`p2`는 사용자·SYSTEM·Administrators만 있는 시험 상위입니다. 작업 폴더 밖 허용 폴더 `rt\pwsh\q\allowed`에는 그룹 읽기 ACE를 줬습니다. 셸은 작업 폴더를 시작 위치로 지정해 실행했습니다.

| 동작 | 상위 목록 ACE 없음 | 사용자 소유 시험 상위에만 목록 ACE(`0x1200a1`, 상속 없음) |
| --- | --- | --- |
| PowerShell 5.1 시작 위치가 작업 폴더 | **0/5**(C:\로 떨어짐) | 5/5 |
| `Get-Content .\a.txt`, `New-Item .\b.txt`, `Resolve-Path ..\ws` | **0/5** | 5/5 |
| 작업 폴더 밖 허용 폴더로 `Push-Location`·`Set-Location` | **0/5**(`Access is denied`) | 5/5 |
| `Set-Location 'C:\Program Files'` | 5/5 | 5/5 |
| cmd 시작 위치·`dir`·`type a.txt`, `cd /d` 허용 폴더·`dir` | 5/5 | 5/5 |
| Python `os.getcwd()`·상대 경로 읽기·쓰기 | 5/5 | 5/5 |

측정 계정이 목록을 볼 수 있는 상위 폴더와 소유자는 다음과 같습니다(ACE 없음 조건, 측정 프로그램의 목록 열기).

| 상위 | 소유자 | 측정 계정의 목록 열기 | 이유 |
| --- | --- | --- | --- |
| `C:\` | TrustedInstaller | 됨 | Users 읽기 |
| `C:\Users` | SYSTEM | 됨 | Users 읽기 |
| `%USERPROFILE%` | SYSTEM | 됨 | 이 PC는 `C:\Users`의 Users·Everyone 읽기를 상속함 |
| 시험 루트, `rt` | 사용자 | 됨 | 시험 루트는 위 복사된 ACE, `rt`는 그룹 읽기 |
| `rt\pwsh`, `p1`, `p2`, `q` | 사용자 | **거부** | 샌드박스 권한 없음 |

- **관리자 소유 상위에 ACE가 필요한 경우는 없었습니다.** `C:\`와 `C:\Users`는 측정 계정이 Users 그룹으로 원래 목록을 볼 수 있습니다.
- PowerShell 5.1은 작업 폴더까지의 상위 중 하나라도 목록을 볼 수 없으면 시작 위치가 C:\로 바뀝니다. 그러면 상대 경로가 모두 C:\ 기준이 됩니다. cmd와 Python은 같은 조건에서 정상이었습니다.
- 막힌 상위는 모두 사용자 소유 시험 폴더였고, 사용자 권한으로 붙인 목록 ACE로 풀렸습니다.
- 이 PC의 프로필 폴더는 소유자가 SYSTEM이지만 사용자에게 모든 권한(`WRITE_DAC` 포함) ACE가 있습니다. 그래서 프로필이 Users 읽기를 상속하지 않는 PC라도 사용자가 UAC 없이 프로필 폴더에 목록 ACE를 붙일 수 있을 것으로 봅니다. 그런 PC에서는 재지 않았습니다.
- 다른 드라이브는 이 PC에 없어 재지 않았습니다.
