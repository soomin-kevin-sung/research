# Windows 에디터 저장 충돌 PoC

사용자가 편집 중인 파일이 외부에서 바뀐 뒤 Ctrl+S를 누르면, 앱이 충돌을 알리고 편집기 초안과 외부 파일을 모두 보존해야 한다. 기존 네이티브 E2E가 커버하는 대용량 텍스트를 사용해 같은 동작을 비교한다.

## 실행 절차

1. Windows 대화형 세션에서 앱 커밋, EXE 경로와 해시, agent-desktop 및 WebView2 버전, OS 빌드, 화면 배율을 기록한다. `agent-desktop status`와 버전에 맞는 `agent-desktop skills get platform`으로 대상 창 조작 가능 여부를 확인한다.
2. 대상 저장소에서 의존성과 Chromium을 준비하고 `npm run test:ui -- test/ui/editor-save.spec.mjs --trace on`을 실행한다. 같은 커밋에서 빌드한 Windows EXE를 사용해 `npm run test:files`도 실행한다. 네이티브 스크립트는 기본적으로 `src-tauri/target/debug/<앱>.exe`를 사용하며 `<APP>_NATIVE_EXE`로 지정할 수 있다. 기준 테스트가 실패하면 그 결과를 먼저 기록한다.
3. 회차마다 새 임시 워크스페이스와 앱 데이터 및 WebView2 프로필을 사용한다. `test/native/files.mjs`처럼 `<APP>_DATA_DIR`와 `WEBVIEW2_USER_DATA_FOLDER`를 지정해 앱을 실행하고, 같은 스크립트의 대용량 UTF-8/CRLF 텍스트 fixture를 준비한다. 앱 UI에서 폴더를 등록하고 파일을 연다.
4. agent-desktop으로 앱 창을 스냅샷하고 편집기에 고유한 초안 토큰을 입력한다. 스냅샷에서 초안과 미저장 상태를 확인한다. 테스트 준비 스크립트가 같은 파일을 외부 토큰으로 덮어쓰고 완료 직후 디스크 해시를 기록한다.
5. agent-desktop으로 해당 편집기에 포커스를 두고 Ctrl+S를 한 번 누른다. 최대 20초 동안 경고, 초안, 미저장 상태를 관찰한 뒤 디스크를 독립적으로 읽는다. UI 변경 뒤에는 새 스냅샷의 참조를 사용한다. 회차 사이에 앱과 fixture를 초기화한다.

## 통과 기준

- 기준 테스트가 통과한 빌드에서 3회 모두 Ctrl+S 후 20초 안에 외부 변경 경고가 나타나고, 해당 편집기에 초안 토큰과 미저장 상태가 남는다.
- 3회 모두 저장 시도 후 파일의 전체 바이트가 외부 덮어쓰기 직후와 일치한다. 일치 여부는 SHA-256으로 비교한다.
- 관찰 가능한 상태가 기대와 다르면 해당 회차는 실패다. UI Automation에서 필수 상태가 노출되지 않거나 실행 환경이 준비되지 않으면 해당 항목은 `판정 불가` 또는 `미실측`으로 기록한다. 화면 캡처와 기존 네이티브 테스트 결과를 함께 보아 접근성 관찰 한계와 앱 동작을 구분한다. 3회와 20초는 초기 PoC에 제안한 기준이다.

## 실패 증거

- 실행 ID와 실패 단계, 시각, 예상·실제 결과, 앱 및 도구 버전, 재현 명령과 종료 코드를 기록한다.
- 저장 직전과 실패 직후의 접근성 JSON과 앱 창 스크린샷, CLI stdout/stderr, 입력 이벤트 시각, 캡처 가능한 앱 로그를 보관한다.
- 초기 파일, 외부 덮어쓰기 직후 및 Ctrl+S 후의 파일 크기·해시를 남긴다. 기준 테스트 실패 시 Playwright trace나 네이티브 테스트 출력·생성된 스크린샷을 연결한다.
- 판정과 증거 위치는 `runs/YYYY-MM-DD-NN.md`에 적고, 원본은 `local/<실행 ID>/`에 둔다. 공개 기록에는 민감한 경로와 화면 내용을 제거한 근거를 남긴다.
