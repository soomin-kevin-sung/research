### Restricted Token 호스트 비정상 종료

조정 프로세스는 qwenpaw를 import하지 않고 시험 프로필로 작업 프로세스를 시작합니다. 작업 프로세스는 Restricted Token 샌드박스에서 `ping -n 37 127.0.0.1`을 시작한 뒤 `stop()`, 제품 정리, atexit를 모두 거치지 않도록 `os._exit(0)`로 끝납니다. 이어서 같은 시험 프로필로 새 프로세스가 `shutdown_cleanup()`만 호출합니다.

| --- | --- | --- | --- | --- |
| 종료 전 자식 | 실행 중 | `PING.EXE` PID 21196(13:53:47 생성)과 작업 프로세스 생존 확인(2회차) | — | 시험 전제 확인 |
| 호스트 비정상 종료 뒤 자식 | 함께 종료 | 직후와 5초 뒤 모두 없음(1/1). 1회차는 종료 전 자식을 관측하지 않아 집계에서 제외 | 자식을 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` Job에 할당합니다(`windows_unelevated_sandbox.py:1058-1073`, `:1953`). | **통과** |

## ISO-11 명명된 파이프와 프로세스

호스트 측 파이프 서버는 보안 설명자를 지정하지 않아 Windows 기본 DACL을 씁니다. 기본 DACL은 생성자 소유자·SYSTEM·Administrators에 전체 권한을, Everyone과 익명에 읽기를 허용합니다. [Windows 파이프 권한](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights) 호스트 대조는 쓰기 3/3, 읽기 1/1(3회차) 성공했습니다.

| 조건 | Restricted Token | AppContainer | 판정 |
| --- | --- | --- | --- |
| 샌드박스 안 익명 파이프(`echo … \| findstr …`) | 3/3 성공 | 3/3 성공 | 내부 통신 가능 |
| 호스트 파이프에 쓰기 | `Access is denied.`, 서버 연결 0회(3/3) | 같음(3/3) | 차단 |
| 호스트 파이프에서 읽기 | 호스트가 보낸 합성 문자열 수신(1/1) | `Access is denied.`, 서버 연결 0회(1/1) | Restricted Token은 같은 사용자가 만든 기본 보안 파이프에서 데이터를 읽을 수 있음. AppContainer는 차단 |
| 자식 프로세스 시작 | ISO-14의 순차 자식 3개 성공 | 같음 | 병렬 빌드와 진단 연결은 미실측 |

Restricted Token 결과는 `WRITE_RESTRICTED`가 쓰기 접근에만 제한 SID 검사를 더한다는 설명과 일치합니다. 1·2회차의 읽기 시험은 호스트 대조에서도 `All pipe instances are busy.`가 나와 무효 처리했습니다. 원인은 서버 인스턴스를 하나씩 다시 만드는 하네스 구조였고, 3회차에서 인스턴스를 미리 여러 개 만들도록 고쳤습니다.

판정에는 종료 코드만 사용합니다. 값은 기록하지 않았고, HKLM 빌드 번호는 `26200` 포함 여부만 확인했습니다. 샌드박스 출력은 400자로 잘랐기 때문에 출력 줄 수는 호스트와 비교하지 않습니다. 호스트 대조는 2·3회차에서 모든 키 성공입니다.

| `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion` `CurrentBuild` | 성공, 26200 3/3 | 성공, 26200 3/3 | — |

- Restricted Token은 같은 사용자의 레지스트리를 그대로 읽습니다.
- AppContainer의 레지스트리 경계는 키 ACL을 그대로 따랐습니다. `HKCU\Environment`처럼 Windows 기본 ACL이 AppContainer 읽기를 허용한 키는 AppContainer에서도 읽힙니다. 따라서 사용자 환경 변수에 둔 비밀은 AppContainer로 보호되지 않습니다.
- 쓰기, 전용 시험 키, 가짜 자격 증명, 세션 간 접근은 실제 레지스트리 하이브 변경을 피하려고 미실측입니다.

## ISO-13 데스크톱과 클립보드

미실측입니다. 실제 사용자 클립보드와 데스크톱은 공유 상태입니다. 읽으면 사용자 데이터가 기록에 남을 수 있고, 쓰면 사용자의 내용이 바뀝니다. 전용 시험 세션이나 VM에서 측정해야 합니다.

> 정정: 내용을 읽지 않고 클립보드를 열 수 있는지만 확인하는 방법은 이 PC에서도 가능했습니다. [2026-11-24-07](2026-11-24-07.md#4-iso-13-클립보드-백엔드마다-5회)에서 측정했습니다.
